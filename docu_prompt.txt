You are a senior C++/Qt 6 desktop application architect and engineer.

Your task is to design and implement a native desktop word-processing application called:

                         DOCU

Docu is a lightweight, classic, Windows-7/WordPad-inspired document editor. It should feel like a traditional desktop application rather than a modern web application or an Electron/Chromium-based application.

The project must be written in:

- C++
- Qt 6
- CMake
- Qt Widgets

Do NOT use Electron.
Do NOT use a web frontend.
Do NOT use Python for the application.
Do NOT use QML unless explicitly requested later.
Do NOT introduce unnecessary third-party frameworks.
Prefer Qt's native APIs wherever possible.

The application should have a clean, maintainable architecture and should be developed incrementally rather than as one enormous monolithic implementation.

============================================================
1. CORE PHILOSOPHY
============================================================

The most important requirement is architectural quality.

Do NOT build the application as one giant MainWindow.cpp.

Do NOT put document logic directly inside button callbacks.

Do NOT tightly couple the GUI to file formats.

Do NOT make the Ribbon/toolbar responsible for modifying document internals directly.

Do NOT create a custom text engine when Qt already provides the required functionality.

The application should be divided into logical layers:

    GUI
      ↓
    Actions / Commands
      ↓
    Document Controller / Document Model
      ↓
    Qt document engine / object management
      ↓
    File I/O / serialization

The GUI should be replaceable without destroying the document engine.

The application should be designed so that future features can be added without restructuring the entire project.

3. A4 PAGE MODEL
============================================================

Use A4 dimensions:

    210 mm × 297 mm

The internal document representation should use an appropriate Qt logical coordinate system.

A4 in points is approximately:

    595.28 × 841.89 pt

Do not simply make an infinitely expanding QTextEdit and call it A4.

The document should understand that it is a page-oriented document.

We need:

    Page width
    Page height
    Margins
    Page orientation
    Zoom

Initially:

    A4
    Portrait
    Reasonable default margins

Later the architecture should allow:

    A4 Portrait
    A4 Landscape
    Other paper sizes
    Custom page sizes

without rewriting the editor.
